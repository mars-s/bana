# Bana roadmap

Bana aims for the core behaviour of the Tana outliner, rebuilt clean-room in Rust, then goes
further on openness, local-first storage and agent control. Status by spec section is in
[docs/parity.md](docs/parity.md).

## Known simplifications

- Undo history is per session (merging another copy keeps it; it takes back only local edits).
- History is compacted only up to what every paired copy has acknowledged; a copy that is not paired keeps it whole.
- Removing a sync device stops its access to the relay; it still knows the key (start sync again for a new key).
- A further workspace has its own Library, Schema and Trash; Today and Daily notes follow the main workspace.
- One local editor: "edited by" is the computer's user, or the assistant whose edit was last (its MCP client name: self-reported, unless it came with a scoped agent token).
- Over `POST /mcp` (no sessions) the `initialize` client name counts only for its own request; a connector names the assistant with `X-Bana-Agent`.
- Scoped agent tokens are kept in plain text in the data folder (readable by the person only), as the local token is; revoking one is deleting its entry from `agent-tokens.json` (or making it again, which replaces it).
- Mirror lookups scan the nodes with the mirror's supertag on each call (fine to thousands of items).
- Off macOS, a few Ctrl and Cmd shortcuts from the spec collapse onto the same key (Ctrl+Shift+D).
